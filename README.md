# Client Research — 客户调研统一编排

把客户的**公开信息（外部调研）**与**微信聊天历史（内部调研）**合并成一张可行动的卡片，回答四件事：**我们能提供什么？客户可能需要什么？谈什么？什么时候切入？**

## 它能做什么

你给一个公司名 + 可选微信联系人，它：

1. **外部调研**：搜索公开信息（行业、规模、关键人、招聘动态、近期新闻）
2. **内部调研**：从微信聊天记录提取关系历史、共享文件、合作信号
3. **按统一 schema 合并**：冲突以内部为准、标注置信度
4. **输出「切入时机」**：下一步动作 + 理由 + 可直接用的话术
5. **推送飞书**：生成文档 + 发消息给你

## 适合 / 不适合

**适合**：
- 要联系一个新客户 / 跟进老客户，需要准备谈资和切入理由
- 同时有公开信息缺口和微信关系历史，不想分开查
- 作为周度自动化，定期刷新重点客户动态

**不适合**：
- 只需要公开信息（用 [lead-card](https://github.com/yang1996202-cpu/lead-card) 更快）
- 只需要整理微信聊天（用 wechat-local-parse）
- 没有微信联系人数据源也不打算用 —— 此时它退化为 lead-card 套壳，不划算

## 需要准备什么

| 输入 | 必填 | 说明 |
|------|------|------|
| 公司名 | ✅ | 如「枫叶互动」 |
| 微信联系人 | 可选 | 如「C-milk周」，给的昵称/备注会匹配微信会话 |
| 你的业务 | 可选 | 默认 pixmax/瑞云 AIGC，可自定义 |

## 输出长什么样

触发后，你会收到一张飞书文档卡片，结构固定为五节：

```
# 客户统一视图：枫叶互动（C-milk周）

## 一、基础档案 / 情况分析
行业、规模、关键人、微信关系现状

## 二、我们能提供什么
你的能力 × 对方痛点，内部信号优先

## 三、客户可能需要什么
缺口 / 信号（微信聊天 > 行业推断）

## 四、谈资
- 内部：真实聊过的人 / 事 / 项目
- 外部：行业话题

## 五、切入时机
- 下一步动作：发邮件约视频会
- 理由：对方刚公布 AI 漫剧战略、郑州招 AI 岗
- 话术由头："看到 ReelShort 今年要单独开 AI 漫剧板块…"
```

## 典型提示词

```
/client-research 枫叶互动
/client-research 第七区 --wx 王方涛
/client-research 字节跳动 --wx 张三 --my-product 企业培训服务
```

## 如何安装

前置：WorkBuddy，且已连接飞书和微信本地数据（wd-local MCP）。

```bash
# 克隆到 WorkBuddy skills 目录
mkdir -p ~/.workbuddy/skills/client-research
cp SKILL.md ~/.workbuddy/skills/client-research/
```

依赖的子 Skill（需一并安装）：
- [lead-card](https://github.com/yang1996202-cpu/lead-card) — 外部调研
- wechat-local-parse — 内部调研（随 WorkBuddy 内置）

## 架构

本 Skill 是**母 Skill（编排层）**：自己不查资料，只负责按顺序编排两个子 Skill 并合并。

```
client-research（母：编排 + 合并规则 + 契约）
├──► lead-card（子：外部调研，可独立调用）
└──► wechat-local-parse（子：内部调研，可独立调用）
```

## 关于数据源

- **公开信息**：通过 WebSearch 获取（企查查、天眼查、官网、招聘、新闻）
- **微信记录**：通过 WorkBuddy 的微信本地数据 MCP（仅解析你已获得的聊天）
- 数据只用于生成卡片，不存储、不外泄
